## 双向循环神经网络

双向 RNN 的动机：

> 有些任务判断当前位置时，不仅要看“前文”，还要看“后文”。

比如填空：

```text
我 ___ 。
我 ___ 饿了。
我 ___ 饿了，我可以吃半头猪。
```

同一个空，后面的上下文不同，答案也可能不同。

普通 RNN 只能从左往右利用过去信息；双向 RNN 会：

- 一条 RNN 从左往右读
- 一条 RNN 从右往左读
- 最后把两边的信息结合起来

所以它适合：

> 文本分类、序列标注、命名实体识别这类“整段文本都已经知道”的任务。

但不适合严格自回归生成，因为生成未来 token 时不能提前看到未来。

### 隐马尔可夫模型中的动态规划

__这里的模型是对什么的建模？rnn吗？__

不是在建模 RNN，而是在建模“序列背后的隐藏状态如何演化，并产生我们看到的观测”。

这里是隐马尔可夫模型 HMM：

```text
隐藏状态：
h1 → h2 → h3 → ... → hT
↓    ↓    ↓          ↓
x1   x2   x3         xT
观测值
```

它假设两件事：

1. 隐藏状态按马尔可夫链变化：

$P(h_{t+1}\mid h_t)$

1. 当前隐藏状态决定当前观测：

$P(x_t\mid h_t)$

例如做词性标注：

```text
隐藏状态 h_t：这个词的词性（名词/动词/形容词）
观测 x_t：真正看到的单词
```

所以 HMM 的任务常常是：

> 已经观察到整段 $x_1,\dots,x_T$，推断背后最可能的隐藏状态序列 $h_1,\dots,h_T$。

这里的 $h_t$ 和 RNN 的 hidden state 名字很像，但不是一回事：

- HMM：概率模型里的隐变量
- RNN：神经网络计算出来的连续向量隐藏状态

这节讲 HMM，主要是为了引出动态规划，以及说明为什么有些序列任务需要同时利用前后文。

__所以这是对现实世界建模的一种概率预测模型？__

对，可以这么理解。

HMM 本质上就是：

> 假设现实里存在一个“看不见的状态”，这个隐藏状态会随时间变化，并产生我们能观察到的数据。

例如天气：

```text
隐藏状态 h_t：晴 / 阴 / 雨
        ↓
观测 x_t：温度、湿度、是否打伞等
```

模型学习两类概率：

$P(h_{t+1}\mid h_t)$

表示“状态怎么变化”。

以及：

$P(x_t\mid h_t)$

表示“某个隐藏状态会产生什么观测”。

所以它既可以做预测，也可以反过来根据观测推断隐藏状态。

一句话：

> HMM 是一种用“隐藏状态 + 概率转移”描述时序现实过程的生成式概率模型。





这里的 $x_{-j}$ 不是“负 j 下标”，而是一种简写：

> $x_{-j}$ 表示“除了 $x_j$ 之外的所有观测”。

也就是：

$x_{-j} = (x_1,\dots,x_{j-1},x_{j+1},\dots,x_T)$

所以：

$P(x_j\mid x_{-j})$

意思就是：

> 已知序列里其他所有位置的值，预测第 $j$ 个位置的值。

比如：

```text
我 今天 ___ 南京
```

如果空缺位置是第 3 个，那么 $x_{-3}$ 就是其余所有已知内容：

```text
我、今天、南京
```

这里的任务就类似“完形填空”：利用左边和右边的上下文一起推断 $x_j$。

一句话：

> 下标 $-j$ 表示“排除第 $j$ 个元素”，不是索引为负数。





这里的意思很简单：

假设每个隐藏状态 $h_t$ 不是任意实数向量，而只能从有限几个状态里选一个。

比如天气 HMM：

```text
h_t ∈ {晴天, 阴天, 雨天}
```

那这里就是：

```text
k = 3
```

因为隐藏状态只有 3 种可能。

如果是词性标注，也可以是：

```text
h_t ∈ {名词, 动词, 形容词, 副词, ...}
```

假设一共 10 种词性，那就是：

```text
k = 10
```

所以“每个 $h_i$ 可以接受 $k$ 个不同的值”就是：

> 每个时间步的隐藏状态，只能从 $k$ 个预定义状态中选一个。

如果序列长度是 $T$，那整条隐藏状态序列：

$h_1,h_2,\dots,h_T$

理论上就有：

$k^T$

种可能组合。

比如 $k=3$，$T=100$：

$3^{100}$

种隐藏状态路径，根本不可能暴力枚举。

所以教材才说：

> 直接把所有隐藏状态组合都试一遍太贵，需要动态规划来高效计算。





这页其实只是在讲 HMM 里最经典的“前向算法”。你先完全忽略那一大坨公式，只抓一个核心：

> 不要把所有隐藏状态路径一条条枚举；走到同一个隐藏状态的所有历史路径，先合并成一个概率，再继续往后算。

这就是动态规划。

假设隐藏状态只有两个：

```text
晴天、雨天
```

我们观察到：

```text
x1, x2, x3, ...
```

如果暴力枚举隐藏状态，3 个时间步就有：

```text
晴 → 晴 → 晴
晴 → 晴 → 雨
晴 → 雨 → 晴
晴 → 雨 → 雨
雨 → 晴 → 晴
...
```

时间步一多，就有 $k^T$ 条路径，直接爆炸。

动态规划的办法是：

> 到时间步 2 时，我根本不关心你之前具体走了哪条路，我只关心“现在处于晴天的总概率”和“现在处于雨天的总概率”。

比如所有最终到达 $h_2=\text{晴}$ 的路径：

```text
晴 → 晴
雨 → 晴
```

把它们的概率直接加起来，压缩成一个数字：

$\pi_2(\text{晴})$

类似地：

$\pi_2(\text{雨})$

于是原来很多条历史路径，现在只保留两个数：

```text
到达“晴”的总概率
到达“雨”的总概率
```

然后进入下一步时，直接从这两个数继续推。

这就是截图里 $\pi_t(h_t)$ 的意义：

> $\pi_t(h_t)$ = 已经解释完前面的观测以后，现在走到隐藏状态 $h_t$ 的“累计概率”。

例如：

$\pi_2(h_2) = \sum_{h_1} P(h_1) P(x_1\mid h_1) P(h_2\mid h_1)$

大白话就是：

> 想知道“走到 $h_2$”有多大概率，就把所有可能的上一状态 $h_1$ 都考虑一遍：
> “以前到这里的概率 × 产生当前观测的概率 × 转移到下一个状态的概率”，最后全部加起来。

然后不断重复：

```text
π1
↓
结合 x1，推到 π2
↓
结合 x2，推到 π3
↓
结合 x3，推到 π4
↓
...
```

所以截图最后的递推式：

$\pi_{t+1}(h_{t+1}) = \sum_{h_t} \pi_t(h_t) P(x_t\mid h_t) P(h_{t+1}\mid h_t)$

你可以直接翻译成人话：

> # “下一时刻处于某个状态的累计概率”
>
> 把“当前所有可能状态 → 下一状态”的所有路线概率加起来。

最重要的是，动态规划把：

$k^T$

条完整路径，变成每个时间步只维护大约 $k$ 个状态值。

所以这页的核心其实只有一句：

> HMM 的前向算法 = 把所有到达同一个隐藏状态的历史路径提前合并，避免重复枚举指数数量的路径。

这和 RNN 的感觉确实有一点像：都是“把过去的信息压缩成当前状态，再往后递推”；但 HMM 这里压缩的是概率，RNN 压缩的是学习出来的隐藏向量。



__如果说刚才的前向递归类似于rnn中的前向传播过程的话，那么这里的后向递归旧类似于rnn中的反向传播是吗？__

不一样，只是“方向上”看起来像。

HMM 的后向递归：

> 从序列末尾往前，计算“未来这些观测，在当前隐藏状态下出现的概率”。

也就是在做概率上的动态规划。

例如：

```text
h_t → h_{t+1} → h_{t+2} → ...
        ↓          ↓
      x_{t+1}    x_{t+2}
```

后向递归是在问：

> 如果当前是 h_t，那么后面这一串观测出现的概率有多大？

它不计算梯度，也不更新参数。

而 RNN 的反向传播/BPTT：

> 从 loss 往前传梯度，计算每个参数对误差的影响，然后用于梯度下降。

所以：

- HMM 前向递归 / 后向递归：概率推断
- RNN 前向传播 / 反向传播：神经网络计算 + 求梯度

共同点只是：

> 一个沿时间向前算，一个沿时间向后算。

但“后向递归”绝对不等于“反向传播”。



__也就是说后向递归其实在操作上跟前向递归是在文本序列上对称的是吧？__

对，可以这么理解。

在文本序列这个“时间轴”上：

- 前向递归：从左到右，把“过去的信息”不断汇总。
- 后向递归：从右到左，把“未来的信息”不断汇总。

所以它们在操作方向上是对称的：

```text
前向：x1 → x2 → x3 → ... → xT
后向：xT → xT-1 → ... → x2 → x1
```

但两者汇总的东西不同：

- 前向递归：当前状态之前的观测概率信息
- 后向递归：当前状态之后的观测概率信息

最后把前向和后向的信息结合起来，就能更好地推断某个位置的隐藏状态。



极简总结：

- 前向递归：从左到右汇总“过去”的概率信息。
- 后向递归：从右到左汇总“未来”的概率信息。
- 两者结合后，可以利用某位置左右两边的全部观测，推断该位置的隐藏状态/缺失观测。
- 计算复杂度从暴力枚举的指数级，降到大约 $O(k^2T)$ 的线性时间尺度。

一句话：

> HMM 的前向-后向算法，就是用动态规划把左右两边的信息分别压缩，再合起来做高效概率推断。



__我很好奇如果算力无限，暴力枚举是怎么算的？算出来每个路径然后呢？最后不应该还是要化成概率然后argmax吗？__

对，但要看你最终想求什么。

如果算力无限，暴力枚举就是：

> 把所有可能的隐藏状态路径全部列出来，算每条路径的联合概率，然后按任务需要“求和”或“取最大”。

比如隐藏状态有 2 种，序列长度 3：

```text
AAA
AAB
ABA
ABB
BAA
BAB
BBA
BBB
```

对每条路径都算：

$P(h_1,h_2,h_3,x_1,x_2,x_3)$

例如：

$P(h_1)P(x_1\mid h_1) P(h_2\mid h_1)P(x_2\mid h_2) P(h_3\mid h_2)P(x_3\mid h_3)$

然后分情况。

如果你想求“这串观测出现的概率”，就把所有路径概率加起来：

$P(x_1,x_2,x_3) = \sum_{h_1,h_2,h_3} P(x_1,x_2,x_3,h_1,h_2,h_3)$

如果你想猜缺失的 $x_j$，那就对每个候选值分别算：

```text
候选 x_j = A
→ 枚举所有隐藏路径
→ 所有路径概率求和
→ 得到 P(x_j=A, x_{-j})

候选 x_j = B
→ 同样计算

候选 x_j = C
→ 同样计算
```

再归一化得到：

$P(x_j\mid x_{-j})$

最后如果要做单点预测，再：

$\arg\max_{x_j}P(x_j\mid x_{-j})$

所以你理解得对：

> 动态规划并没有改变最终要算的概率；它只是避免真的把指数数量的路径一条条列出来。

如果要找“最可能的隐藏状态整条路径”，那又是另一件事：直接对所有路径概率做 argmax，这对应 Viterbi 算法。





### 双向模型

![image-20260918130351498](/home/yang-zhi/桌面/learning-notes/assets/images/image-20260918130351498.png)

双向 RNN = 两个方向各跑一个 RNN：

- 正向 RNN：从左到右，利用过去信息。
- 反向 RNN：从右到左，利用未来信息。

在时间步 $t$，把两边的隐藏状态结合起来，再产生输出。

直觉上：

```text
过去 → 当前 ← 未来
        ↓
      输出
```

所以它特别适合：

> 已经拿到完整序列、需要同时看左右上下文的任务。

比如命名实体识别、文本标注、完形填空。

但不适合严格自回归生成，因为生成当前 token 时未来内容还不存在。



正式定义双向 RNN 的计算方式。

核心流程：

- 正向 RNN：从左到右计算隐藏状态 $\overrightarrow{H_t}$，利用过去信息。
- 反向 RNN：从右到左计算隐藏状态 $\overleftarrow{H_t}$，利用未来信息。
- 两个方向使用各自独立的参数，不共享权重。
- 在时间步 $t$，把两个隐藏状态拼接：

$H_t= [\overrightarrow{H_t},\overleftarrow{H_t}]$

如果两个方向各有 $h$ 个隐藏单元，拼接后就是 $2h$ 维。

最后再用这个包含“过去 + 未来”信息的 $H_t$ 计算输出：

$O_t=H_tW_{hq}+b_q$

一句话：

> 双向 RNN = 两个方向各跑一个 RNN，再把同一位置的两个隐藏状态拼起来，让输出同时利用左右上下文。



__左右不一定要都是h吧，应该可以h+i这种形式？__

对，完全可以。

前向隐藏维度不一定等于反向隐藏维度。比如：

- 前向：$h_f$ 维
- 反向：$h_b$ 维

拼接后就是：

$h_f+h_b$

维。

比如：

```text
前向：128维
反向：64维
↓ 拼接
192维
```

教材写成 $2h$，只是为了简化，默认两个方向都用了 $h$ 个隐藏单元。

所以你说的“$h+i$ 这种形式”思路是对的，更规范一般写成：

$h_f+h_b$

而不是必须 $2h$。
