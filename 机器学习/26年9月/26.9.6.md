# 循环神经网络

## 循环神经网络

### 无隐状态的神经网络

这里是在先回顾一个普通的单隐藏层神经网络，为后面 RNN 做对比。

普通网络的流程很简单：

```text
输入 X
  ↓
隐藏层
  ↓
隐藏表示 H
  ↓
输出层
  ↓
输出 O
```

隐藏层计算：

$H=\phi(XW_{xh}+b_h)$

直觉就是：

> 输入 $X$ 经过一次线性变换，再过激活函数，得到隐藏表示 $H$。

其中 $W_{xh}$ 是“输入 → 隐藏层”的权重。

然后输出层：

$O=HW_{hq}+b_q$

也就是：

> 再把隐藏表示 $H$ 映射成最终输出 $O$。

如果是分类问题，再对 $O$ 做 softmax，就得到各类别概率。

截图里最重要的是标题：“无隐状态”。

这里虽然有隐藏层 $H$，但没有“隐藏状态”。

区别在于：

> 普通 MLP 每次只根据当前输入 $X$ 算输出，不会记住上一次输入的信息。

例如连续输入：

```text
x1 → 网络 → y1

x2 → 网络 → y2

x3 → 网络 → y3
```

三次计算互相没有记忆。

而后面的 RNN 会变成：

```text
x1 → h1
      ↓
x2 → h2
      ↓
x3 → h3
```

其中 $h_2$ 会利用 $h_1$，$h_3$ 又会利用 $h_2$。

所以这一节本质是在说：

> 普通神经网络只有“隐藏层”，没有跨时间保存信息的“隐藏状态”；下一节给它加上记忆，就得到 RNN。

### 有隐状态的神经网络

这一页是在正式把“记忆”加进神经网络，于是普通 MLP 就变成了 RNN。

普通网络在时间步 $t$ 只看当前输入 $X_t$：

$H_t=\phi(X_tW_{xh}+b_h)$

RNN 多看一项：上一个时间步留下来的隐藏状态 $H_{t-1}$。

所以变成：

$H_t = \phi( X_tW_{xh} + H_{t-1}W_{hh} + b_h )$

直觉上就是：

```text
当前输入 X_t
      +
过去的记忆 H_{t-1}
      ↓
    RNN
      ↓
新的记忆 H_t
```

其中：

- $W_{xh}$：当前输入 → 隐藏状态
- $W_{hh}$：上一时刻隐藏状态 → 当前隐藏状态
- $H_{t-1}$：过去信息的“压缩记忆”
- $H_t$：更新后的记忆

然后当前隐藏状态还能用来产生输出：

$O_t=H_tW_{hq}+b_q$

所以一个时间步其实做两件事：

```text
X_t + H_{t-1}
      ↓
     H_t
    ↙   ↘
输出 O_t   传给下一时刻
            ↓
          H_{t+1}
```

这就是为什么叫“循环”神经网络：

> 当前的隐藏状态，会被送到下一个时间步，再参与下一次计算。

例如处理：

```text
我 → 喜欢 → 深度 → 学习
```

可以想成：

```text
“我”
↓
H1：记住“我”

“喜欢” + H1
↓
H2：记住“我喜欢”

“深度” + H2
↓
H3：记住“我喜欢深度”

“学习” + H3
↓
H4
```

当然现实中的 $H_t$ 不是把文字原封不动保存下来，而是一个向量形式的压缩表示。

还有一个非常重要的点：

> 所有时间步共享同一组参数。

也就是说，不是时间步 1 有一套 $W_{xh}$，时间步 2 又换一套，而是：

```text
t=1：使用 W_xh、W_hh
t=2：还是使用 W_xh、W_hh
t=3：还是使用 W_xh、W_hh
...
```

所以序列变长，并不会让模型参数量跟着增长。

一句话总结：

> RNN = 当前输入 + 上一时刻记忆 → 当前记忆；当前记忆既用于产生输出，也继续传给下一时刻。

### 所有时间步共享同一组参数。

可以把 RNN 想成“同一个小机器，被反复调用很多次”。

比如序列是：

```text
我 → 喜欢 → 深度 → 学习
```

RNN 实际上做的是：

```text
同一个 RNN 单元处理“我”
↓
还是同一个 RNN 单元处理“喜欢”
↓
还是同一个 RNN 单元处理“深度”
↓
还是同一个 RNN 单元处理“学习”
```

每次调用时，变的是输入和隐藏状态：

```text
t=1：输入 x1，旧记忆 h0
t=2：输入 x2，旧记忆 h1
t=3：输入 x3，旧记忆 h2
```

但里面使用的权重始终是同一套：

$W_{xh},\quad W_{hh}$

所以虽然画图时看起来像：

```text
[RNN] → [RNN] → [RNN] → [RNN]
```

其实更准确地理解成：

```text
同一个 RNN
第1次调用
第2次调用
第3次调用
第4次调用
```

不是复制了 4 个不同的网络。

因此即使序列从 10 个 token 变成 1000 个 token，只是“同一个网络多运行了几次”，不会因此多出新的参数。

一句话：

> 时间步增加的是计算次数和隐藏状态，不是模型参数数量。

### 困惑度（Perplexity）

困惑度（Perplexity）用来衡量语言模型“对下一个 token 有多不确定”。

核心理解：

> 困惑度 ≈ 模型平均觉得“下一个 token 有多少个等可能选项”。

所以：

- 困惑度 = 1：完美预测。
- 困惑度越小越好。
- 如果词表有 $V$ 个词，而模型完全瞎猜、均匀分布，那么困惑度约为 $V$。
- 如果正确 token 的概率趋近 0，困惑度会趋近无穷大。

一句话：

> 困惑度越低，说明模型越能准确预测下一个 token。

### 小结：

对隐状态使用循环计算的神经网络称为循环神经网络（RNN）。

循环神经网络的隐状态可以捕获直到当前时间步序列的历史信息。

循环神经网络模型的参数数量不会随着时间步的增加而增加。

我们可以使用循环神经网络创建字符级语言模型。

我们可以使用困惑度来评价语言模型的质量。

### 预测-热身

这段在讲：训练好的 RNN 怎么“续写文本”。

假设用户给一个前缀：

```text
time traveller
```

模型要在后面继续生成字符。

第一步叫“预热（warm-up）”。

RNN 的隐藏状态一开始是空的。于是先把前缀一个字符一个字符喂进去：

```text
t → h1
i + h1 → h2
m + h2 → h3
e + h3 → h4
...
```

这期间虽然模型也会产生预测，但我们不采用，因为真实前缀已经告诉模型下一个字符是什么。

目的只是：

> 让隐藏状态先“读懂”前缀，把 `time traveller` 的上下文信息装进隐藏状态。

前缀读完后，才真正开始生成。

之后流程是：

```text
当前字符 + 当前隐藏状态
        ↓
       RNN
        ↓
下一个字符的概率分布
        ↓
选概率最大的字符
        ↓
把这个字符重新作为下一步输入
        ↓
继续生成
```

代码里的：

```python
y.argmax(dim=1)
```

就是选择概率/得分最高的下一个字符。

所以生成过程是自回归的：

```text
time traveller
       ↓
预测字符1
       ↓
用字符1预测字符2
       ↓
用字符2预测字符3
       ↓
...
```

截图最后得到：

```text
time traveller aaaaaaaaaa
```

是因为此时网络还没训练，权重基本是随机的，所以输出没有语言规律，连续选中了 `a`。

一句话：

> 先用 prefix 更新 RNN 的“记忆”，然后让模型不断把自己刚生成的字符作为下一步输入，逐字符续写文本。

### 为啥一定要预热，为啥不能边生成边传递隐藏状态，这在时间步上并不冲突啊？

其实你说的“边生成边传递隐藏状态”完全可以，而且 RNN 本来就是这么做的。

所谓“预热”并不是另一套机制。它只是说：

> 对于已经给定的 prefix，我们只更新隐藏状态，不采用模型的预测结果。

隐藏状态一直在正常传递，没有中断。

例如 prefix 是：

```text
time
```

过程其实是：

```text
输入 t → 得到 h1，同时模型也预测下一个字符
输入 i → 得到 h2，同时模型也预测下一个字符
输入 m → 得到 h3，同时模型也预测下一个字符
输入 e → 得到 h4
```

模型前几步其实已经在“预测”了，只不过我们忽略这些预测，因为下一个字符 `i、m、e` 已经由用户明确给定。

等 prefix 读完：

```text
time → h4
```

才开始采用模型预测：

```text
h4 → 预测 x5
x5 + h4 → h5 → 预测 x6
...
```

所以不存在时间步冲突。

更准确地说：

> “预热” = 用真实 prefix 驱动 RNN，把上下文装进隐藏状态；
> “生成” = prefix 用完之后，改用模型自己预测的 token 继续驱动 RNN。

如果根本没有 prefix，只给一个 `<bos>`，那就可以从第一个时间步直接自回归生成，不需要预热。

### 哦，所以这本质上就是一个前缀注入是吗？

对，可以这么理解。

更准确地说：

> 预热 = 把 prefix 逐步注入 RNN，让隐藏状态先编码这段上下文。

比如：

```text
prefix: time traveller
        ↓
不断更新隐藏状态
        ↓
得到带有“time traveller”上下文的 h
        ↓
从这个 h 开始继续生成
```

所以它本质上就是“用前缀初始化/塑造隐藏状态”。

和现代 LLM 的 prompt conditioning 直觉上也很像：先给上下文，再基于这个上下文继续生成。

### prefix cache是不是也跟这个有关。

对，直觉上有关，但机制不同。

你刚才说的 RNN 预热是：

> 把 prefix 喂进去，得到一个已经包含上下文信息的隐藏状态。

现代 Transformer 里的 prefix cache 更像：

> 某段 prefix 以前已经算过了，就把这段 prefix 对应的中间结果缓存下来，下次直接复用，不再重复计算。

通常缓存的是这段前缀各层的 KV cache。

例如很多请求都以：

```text
You are a helpful assistant...
```

开头，那么这段固定前缀可以提前算一次并缓存。

所以可以类比成：

```text
RNN：
prefix → 算出隐藏状态 h → 接着生成

Transformer：
prefix → 算出各层 KV → 缓存 → 接着生成
```

共同点都是：

> 先把前缀“消化”成模型内部状态，再从这个状态继续生成。

区别是 RNN 主要压缩成一个递归隐藏状态；Transformer 会保留前缀各 token 的 KV 表示。
