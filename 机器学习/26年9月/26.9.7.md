# 循环神经网络(RNN)

## 通过时间反向传播

这页在讲：RNN 的反向传播为什么比普通网络麻烦，以及“通过时间反向传播（BPTT）”到底是什么。

先看 RNN 前向过程：

```text
x1 → h1 → h2 → h3 → ... → hT
      ↑     ↑     ↑
     x2    x3    xT
```

每个隐藏状态都依赖前一个隐藏状态：

$h_t=f(x_t,h_{t-1})$

所以最后时刻的损失，不只和当前参数有关，还可能通过隐藏状态一路追溯到很早以前。

比如：

```text
x1
↓
h1 → h2 → h3 → h4
                ↓
               loss
```

反向传播时，梯度就必须沿这条时间链一路往回传：

```text
loss
 ↓
h4
 ↓
h3
 ↓
h2
 ↓
h1
```

这就是 BPTT：

> 把 RNN 沿时间展开成一个很深的网络，然后按普通反向传播的方法，从后往前算梯度。

问题也就出现了。

假设序列有 1000 个时间步，那么梯度可能连续乘 1000 次类似的 Jacobian/权重矩阵。

于是容易发生：

- 连乘整体越来越大 → 梯度爆炸
- 连乘整体越来越小 → 梯度消失

而且如果真把 1000 个时间步全部保留在计算图里：

> 显存/内存和计算开销也会很大。

所以实践中常用“截断 BPTT”。

例如只允许梯度往前传 35 个时间步：

```text
更早历史 | 最近35步 | 当前
         ✂
       截断梯度
```

隐藏状态的数值仍然可以继续传给后面的时间步，但梯度不再穿过这个截断点往更早传播。

这就是你之前看到 `detach()` 的作用：

> 保留隐藏状态的值，但切断它和更早计算图之间的梯度联系。

所以整页可以压缩成：

> RNN 前向时隐藏状态沿时间不断传递；训练时梯度也要沿时间反向传递，这叫 BPTT。序列太长会带来梯度爆炸/消失和巨大计算开销，因此实际中常用梯度裁剪和截断 BPTT。

### 这是不是就是activation checkpointing?

不是。两者目的不同。

截断 BPTT / `detach()`：

> 直接切断更早时间步的梯度，不再对那部分做反向传播。

效果是：

- 省显存
- 省计算
- 但牺牲了超长距离的梯度传播

Activation Checkpointing：

> 不切断梯度，只是不保存某些中间激活；反向传播时再重新 forward 计算一次。

效果是：

- 省显存
- 计算变多
- 梯度仍然能完整传回去

可以记成：

```text
截断 BPTT：
不要这段梯度了

Activation Checkpointing：
梯度要保留，但激活先不存，之后重算
```

所以它们都能省显存，但机制完全不同。

### 但是截断了这部分梯度后，我怎么进行反向传播梯度下降？

可以，因为“截断”不是把所有梯度都删掉，而是只让梯度在最近一段时间窗口里传播。

比如设截断长度是 3：

```text
h1 → h2 → h3 | h4 → h5 → h6 | h7 ...
             ↑              ↑
           detach         detach
```

训练 `h4,h5,h6` 这一段时，前向计算仍然会用到 `h3` 的数值：

$h_4=f(x_4,h_3)$

但 `h3` 被 `detach()` 后，会被当成一个“常量输入”。

于是反向传播可以正常算：

```text
loss6
 ↓
h6
 ↓
h5
 ↓
h4
 ↓
停止在 h3
```

所以这一段里的共享参数，比如 $W_{xh},W_{hh}$，仍然会得到梯度，并正常做梯度下降。

关键是：RNN 每个时间步共享同一套参数。

因此虽然梯度只从最近几个时间步产生，但更新的仍然是全局共享的：

$W_{xh},\quad W_{hh}$

下一批时间步又会产生新的梯度，再继续更新同一套参数。

所以可以理解成：

> 截断 BPTT 不是“不训练”，而是每次只根据最近一段序列来训练共享参数，不让梯度无限往历史深处传播。

### 什么意思？意思是冻结一部分隐藏层的参数，训练部分参数以减少计算负担吗？

不是。没有“冻结一部分参数”。

RNN 在所有时间步共享同一套参数，所以并不存在“前半段时间步用一套参数、后半段再训练另一套参数”。

截断 BPTT 截断的是：

> 梯度沿时间往前传播的路径。

不是参数。

例如：

```text
h1 → h2 → h3 | h4 → h5 → h6
             ↑
           detach
```

训练 `h4~h6` 时：

- `h3` 的数值照样拿来算 `h4`
- 但梯度不会从 `h4` 再穿过 `h3` 回到更早的 `h2,h1`
- 当前这段里用到的共享参数 $W_{xh},W_{hh}$ 仍然正常计算梯度、正常更新

所以更准确地说：

> 截断 BPTT = 保留历史状态的“值”，但不保留无限长的“梯度依赖链”。

这样减少的是反向传播的计算图长度和显存，而不是冻结部分模型参数。

### 什么意思？那么这样牺牲的是什么？截断BPTT的目的是什么？BPTT是什么？为什么所有时间步会共享同一套参数？难道RNN不需要多层感知机不同层来学习数据的不同特征吗？都是同一套参数机器怎么区分简单特征，中等特征，复杂特征的学习？

这里你把“时间步”和“神经网络的层”混在一起了。把这两个维度分开，整个问题就清楚了。

RNN 同时有两个方向：

```text
① 网络深度方向：不同层
② 时间方向：同一层在不同时间反复运行
```

比如一个 2 层 RNN：

```text
          时间 →
        t=1      t=2      t=3

第2层   h²₁  →   h²₂  →   h²₃
         ↑        ↑        ↑
第1层   h¹₁  →   h¹₂  →   h¹₃
         ↑        ↑        ↑
输入     x₁       x₂       x₃
```

这里：

- 第 1 层和第 2 层有不同参数，可以学习不同层次的特征。
- 但第 1 层在 $t=1,t=2,t=3$ 使用同一套参数。
- 第 2 层同理，也有自己的一套参数，并在所有时间步共享。

所以“时间步共享参数”并不等于“所有隐藏层共享参数”。

为什么时间步要共享参数？

因为 RNN 假设：

> “处理序列中下一个元素的规则”在不同位置应该是相同的。

例如：

```text
我 → 喜欢 → 深度 → 学习
```

同一个 RNN 单元不断执行：

$h_t=f(x_t,h_{t-1};W)$

虽然 $W$ 一样，但每次的 $x_t$ 和 $h_{t-1}$ 都不同，所以得到的隐藏状态完全可以不同。

类似于同一个 CPU 执行同一段程序，但输入和内存状态不同，结果当然不同。

这样还有一个巨大好处：

> 序列长度可以任意变化，而参数量不会随着序列长度增长。

------

BPTT 是什么？

BPTT = Backpropagation Through Time，中文“通过时间反向传播”。

RNN 前向传播：

```text
x₁ → h₁ → h₂ → h₃ → h₄ → loss
```

因为 $h_4$ 依赖 $h_3$，$h_3$ 又依赖 $h_2$，所以当前损失实际上可能受到很早以前输入的影响。

训练时就要沿时间往回追：

```text
loss
 ↓
h₄
 ↓
h₃
 ↓
h₂
 ↓
h₁
```

这就是 BPTT。

本质上：

> 把 RNN 在时间上展开，然后对这个展开后的计算图做普通反向传播。

------

那截断 BPTT 又是什么？

假设序列有 10000 个 token。

完整 BPTT：

```text
当前 loss
← 10000步
← 9999步
← ...
← 第1步
```

这样有三个问题：

- 计算量巨大
- 需要保存大量激活，显存巨大
- 梯度连续乘很多次，很容易消失或爆炸

所以实际中常规定：

> 梯度最多往回传 $k$ 个时间步。

例如 $k=3$：

```text
h₁ → h₂ → h₃ | h₄ → h₅ → h₆
              ↑
            detach
```

前向传播仍然使用 $h_3$：

$h_4=f(x_4,h_3)$

但反向传播到 $h_3$ 就停止。

所以截断的是“梯度依赖”，不是隐藏状态，也不是模型参数。

------

那牺牲了什么？

牺牲的是：

> 长距离的信用分配（credit assignment）。

例如：

```text
第 1 个 token
   ↓
影响了第 1000 个 token 的预测
```

完整 BPTT 理论上可以让第 1000 步的 loss 告诉模型：

> “你第 1 步处理得不好，所以现在预测错了。”

如果只截断 100 步，那么这个梯度无法一路传回第 1 步。

因此：

```text
截断越短
→ 计算越便宜、显存越少

但
→ 越难直接学习非常长距离的依赖
```

------

最后回答你“简单特征、中等特征、复杂特征怎么办”。

这主要是“网络层数”负责，不是“时间步数”负责。

例如深层 RNN：

```text
输入 token
   ↓
RNN 第1层：较低层表示
   ↓
RNN 第2层：更复杂表示
   ↓
RNN 第3层：更高层表示
   ↓
输出
```

而每一层内部又沿时间递归：

```text
第1层：h¹₁ → h¹₂ → h¹₃ → ...
第2层：h²₁ → h²₂ → h²₃ → ...
第3层：h³₁ → h³₂ → h³₃ → ...
```

所以你可以把两个轴彻底分开记：

> 深度轴负责“逐层提取复杂特征”；时间轴负责“把历史信息向未来传递”。

而 BPTT 处理的主要就是“时间轴上的反向传播”。

### 可是这样一看，时间步好像更像是对上一层输入的一个处理，类似于卷积层那种感觉，所以参数可以复用。那么BPTT的意义又是什么？反向传播难道不是为了梯度下降吗？从BPTT开始我就没懂，截断BPTT更不要说了。

你这个直觉已经很接近了：

> 时间步可以理解成“同一个 RNN 单元被重复使用很多次”，确实有点像卷积核在不同位置重复使用。

真正卡住你的地方是：既然参数复用了，为什么还需要 BPTT？

因为“参数复用”只解释了前向传播怎么计算；而训练时还必须回答：

> 这套共享参数到底对最终误差负了多少责任？

这就是 BPTT 的作用。

假设只有 3 个时间步：

```text
x1 → h1 → h2 → h3 → loss
      ↑     ↑     ↑
     同一套参数 W
```

前向传播时，同一个 $W$ 被用了 3 次：

$h_1=f(x_1,h_0;W)$$h_2=f(x_2,h_1;W)$$h_3=f(x_3,h_2;W)$

最后产生 loss。

现在要梯度下降，就必须求：

$\frac{\partial L}{\partial W}$

问题是：$W$ 不只在最后一步影响了 loss。

它还通过：

```text
W → h1 → h2 → h3 → loss
```

以及：

```text
W → h2 → h3 → loss
```

以及：

```text
W → h3 → loss
```

影响最终损失。

所以反向传播必须沿着时间链一路往回追，把同一个 $W$ 在各个时间步产生的梯度贡献全部算出来并累加。

这就是 BPTT：

> BPTT 就是普通反向传播，只不过 RNN 的计算图在“时间方向”上展开了，所以梯度也要沿时间方向往回传。

你可以直接把它看成：

```text
前向传播：

x1 → h1 → h2 → h3 → loss

反向传播：

loss → h3 → h2 → h1
          ↓     ↓     ↓
          都在计算共享参数 W 的梯度
```

所以“BPTT”和“梯度下降”不是两个不同东西：

```text
BPTT
↓
计算梯度

梯度下降 / Adam
↓
利用梯度更新参数
```

就像普通 MLP：

> backprop 负责算梯度，optimizer 负责拿梯度更新参数。

------

那为什么要“Through Time”？

普通 MLP 是沿网络深度反传：

```text
Layer3 → Layer2 → Layer1
```

RNN 除了有深度，还多了一个时间依赖：

```text
h3 → h2 → h1
```

所以要沿时间反传，才叫 Backpropagation Through Time。

------

截断 BPTT 就更简单了。

假设真实序列有 1000 步。

完整 BPTT：

```text
loss
← h1000
← h999
← h998
← ...
← h1
```

这条链太长：

- 显存开销大
- 计算开销大
- 容易梯度消失 / 爆炸

于是我们说：

> 算了，当前 loss 最多只往前追 50 步。

于是：

```text
更早历史 | 最近50步 | loss
         ✂
       到这里停止
```

这就是截断 BPTT。

前向传播仍然可以一直传隐藏状态：

```text
h1 → h2 → ... → h1000
```

只是反向传播不无限往前追。

牺牲的是：

> 当前误差无法直接告诉非常久以前的时间步“你当初哪里做错了”。

因此截断 BPTT 本质是一个折中：

```text
完整 BPTT
长距离信用分配更完整
但贵、难训练

截断 BPTT
只追最近一段历史
更便宜、更稳定
但牺牲超长距离梯度信息
```

你现在最该记住的一句话是：

> RNN 前向时，隐藏状态沿时间向后传；BPTT 训练时，梯度沿这条时间链反向传，从而计算共享参数应该怎样更新。

### 哦，我好像有点懂了。是不是RNN的训练过程其实是这样子的。t_n预测t_n+1，而这一步是在时间步这个轴上完成的，而不是隐藏层，隐藏层只负责把上一轮的语义保存送入下一层。然后t_n+1预测与验证不一样的时候，就通过时间步进行反向传播，更新当前层数的W权重。而由于文本是一个长序列，反向传播链式法则又需要存储每一个时间步的梯度，这样显存的压力非常大。于是退而求其次，选择loss前n步进行反向传播。而代价就是丢失了前n步之前的语义，但其实也并不算完全丢失，因为每一层隐藏层的权重都包含了每一个n步反向传播训练的权重。

大方向已经对了，但有几个关键点需要纠正。

你可以把 RNN 训练理解成：

```text
x_t + h_{t-1}
      ↓
     RNN
      ↓
h_t ─────→ 预测 x_{t+1}
 ↓
传给下一个时间步
```

其中：

- $h_t$ 是隐藏状态，不是“隐藏层”。它负责把过去的信息压缩后继续向未来传递。
- 时间步 $t$ 根据当前输入和过去隐藏状态，预测下一个 token。
- 预测结果与真实的 $x_{t+1}$ 比较，产生 loss。这里叫“训练标签”，不是验证集。

然后 BPTT 做：

```text
loss_t
  ↓
h_t
  ↓
h_{t-1}
  ↓
h_{t-2}
  ↓
...
```

沿时间轴反向追踪，计算共享参数 $W$ 的梯度。

注意：不是“更新当前时间步的 W”。

所有时间步使用的是同一套 $W$：

$W_{t=1}=W_{t=2}=W_{t=3}=\cdots$

各时间步产生的梯度贡献最终都会累积到这套共享参数上。

你对显存压力的理解也基本对，但更准确的是：

> 完整 BPTT 为了反向传播，需要保留大量时间步的隐藏状态、激活值等计算图中间量，而不是提前保存“每一步的梯度”。

序列越长，计算图越长，因此显存和计算量越大。

所以截断 BPTT 比如只反传最近 100 步：

```text
很早的历史 → h_{t-100} | h_{t-99} → ... → h_t → loss
                       ✂
                    梯度停止
```

最重要的一点：截断后并没有丢掉前 100 步之前的“语义”。

因为前向传播仍然是：

```text
很早以前的信息
      ↓
h_{t-100}
      ↓
h_{t-99}
      ↓
...
      ↓
h_t
```

所以早期信息仍可能通过隐藏状态传到现在。

真正丢掉的是：

> 当前这个 loss 无法把梯度直接传回 100 步以前，告诉模型“很久以前那个处理方式导致了现在的错误”。

这叫丢失长距离的 credit assignment（信用分配）。

所以最准确的总结是：

> RNN 用隐藏状态沿时间向前传递历史信息；BPTT 用梯度沿时间向后追责；截断 BPTT 保留前向的长期信息传递，但限制反向的长期追责距离。

你最后一句“共享权重经过很多个截断窗口反复训练”，这个方向是对的；但它并不能等价替代一次真正跨越超长距离的梯度传播。

### 为什么会丢失长距离的credit assignment呢？我们这里先不看时间步，只看隐藏层的话，比如我们设定的时间步反向传播的距离为50,那么比如一个token长度为200的文本序列，我的第一层隐藏层的W（这一层的所有时间步共享这个W）就存储了第一个token的信息，第二层两个.......第50层前50个token，第51层2-51个token......最后一层第151-200个token，这样整体来看的话，RNN也是学习了所有的信用分配的呀？每一层的“短距离学习”累和成为一个整体性强的模型不行吗？

你这里最关键的误区是：又把“时间步”当成了“不同隐藏层”。

在一个单层 RNN 里，并不存在：

> 第 1 层 W 学 token 1，第 2 层 W 学 token 1~2，……第 200 层 W 学 151~200。

实际上只有同一个 RNN 层、同一套参数 $W$，被调用 200 次：

```text
token1   ─┐
token2   ─┤
token3   ─┤→ 都调用同一个 RNN(W)
...
token200 ─┘
```

真正随时间变化的是隐藏状态：

```text
h1 → h2 → h3 → ... → h200
```

其中 $h_t$ 存的是“这个具体序列到目前为止的信息”；而 $W$ 学的是“遇到输入和旧记忆时，应该怎样更新记忆”的通用规则。

现在假设有一个极端任务：

```text
token 1：A 或 B
...
中间 198 个 token 都无关
...
token 200：要求模型根据 token 1 回答 A/B
```

也就是说，只有第 200 步的 loss 才告诉模型：

> “你 199 步以前看到的那个 token 很重要，你应该一直记住它。”

完整 BPTT 可以：

```text
loss200
  ↓
h200
  ↓
h199
  ↓
...
  ↓
h1
  ↓
告诉 W：
“你必须学会让 token1 的信息一路保存到 200。”
```

如果截断长度是 50：

```text
h1 → ... → h150 | h151 → ... → h200 → loss200
               ✂
```

那么第 200 步的错误最多只能追责到第 151 步。

它无法告诉第 1~150 步：

> “你们当时应该把 token1 保存得更好，因为 200 步之后我要用。”

这就是长距离 credit assignment 丢失。

你说的“每个 50 步窗口都训练，最后累积起来不就行了吗？”——有时确实能间接做到一部分，这也是截断 BPTT 实际上仍然有效的原因。

但关键问题是：

> 前面的窗口不知道“后面 150 步之后到底需要什么”。

例如第 1~50 步训练时，如果它自己的局部 loss 根本不需要记住 token1，那么梯度没有理由告诉 $W$：

> “请把 token1 保存 150 步，未来有用。”

共享 $W$ 只能把各窗口实际收到的训练信号汇总起来，它不能凭空创造被截断掉的远距离训练信号。

从梯度角度也可以看得很直接。

完整 BPTT 中，第 200 步 loss 对 $W$ 的梯度包含：

$\frac{\partial L_{200}}{\partial h_{200}} \frac{\partial h_{200}}{\partial h_{199}} \cdots \frac{\partial h_2}{\partial h_1} \frac{\partial h_1}{\partial W}$

这一项明确表达：

> “第 1 步使用 W 的方式，如何影响了第 200 步的错误。”

截断到 50 步以后，这一整项直接没了。

所以你可以这样区分：

```text
前向传播：
h1 → h2 → ... → h200
长期信息理论上仍然可以一路传递

反向传播：
loss200 → h200 → ... → h151
                         ✂
无法追责到更早时间
```

因此 TBPTT 牺牲的不是“模型完全不能记住 50 步以前的信息”，而是：

> 模型很难通过一个发生在很久以后的错误，直接学习“很久以前的信息应该怎样保存”。

你提出的“很多局部学习最后组成一个整体”确实是 TBPTT 能工作的原因之一；但“局部训练覆盖了所有位置”不等于“覆盖了所有跨位置的长距离依赖”。这两个概念是不同的。

### 你越说我越懵了，RNN到底是什么？难道你刚才还说他是有两个方向的，一个网络深度方向，一个时间方向。你现在又改口说只有一个RNN层。我的意思就是虽然每一个RNN层是”短视“的，但是多个RNN层进行累和就是”整体“的啊。

这里是我前面举“单层 RNN”例子时没有把范围说清楚。RNN 确实可以有多个层，而且确实有两个轴：

```text
                 时间轴 →
             t=1      t=2      t=3      ...

RNN 第3层     h³₁  →   h³₂  →   h³₃
               ↑        ↑        ↑
RNN 第2层     h²₁  →   h²₂  →   h²₃
               ↑        ↑        ↑
RNN 第1层     h¹₁  →   h¹₂  →   h¹₃
               ↑        ↑        ↑
输入           x₁       x₂       x₃
```

这两个方向负责完全不同的事情。

纵向的“网络深度”：

```text
x_t
 ↓
第1层
 ↓
第2层
 ↓
第3层
```

负责在同一个时间步里，把表示逐层加工得更复杂。和 MLP 的多层很类似。

横向的“时间”：

```text
h₁ → h₂ → h₃ → h₄ → ...
```

负责把过去的信息传向未来。

所以你说：

> 多个 RNN 层累加以后形成更整体的表示。

这句话本身是对的，但这个“整体”是特征层次上的整体，不等于拥有更长的时间梯度范围。

比如 3 层 RNN，TBPTT 截断长度 = 50。

在第 200 个 token 处产生 loss，反向传播可以：

```text
第3层
 ↓
第2层
 ↓
第1层
```

穿过所有 3 个网络层，这是纵向传播。

同时还能：

```text
t=200 → 199 → 198 → ... → 151
```

沿时间向前追 50 步。

但到了 t=150 的截断线，所有层的时间梯度都断了：

```text
        更早时间                    当前窗口

第3层 → h³₁₅₀ | h³₁₅₁ → ... → h³₂₀₀ → loss
              ✂
第2层 → h²₁₅₀ | h²₁₅₁ → ... → h²₂₀₀
              ✂
第1层 → h¹₁₅₀ | h¹₁₅₁ → ... → h¹₂₀₀
              ✂
```

所以不能理解成：

```text
第1层看50步
+
第2层再看50步
+
第3层再看50步
=
看150步
```

不是这样。

因为“层数”和“时间距离”是两个正交的维度。

最关键的一句话：

> 多层 RNN 解决“同一个时间点的信息要加工多少层”；BPTT 解决“当前的错误要沿时间往过去追责多远”。

而截断 BPTT 限制的是后者。

再举一个非常极端的例子：

```text
token 1：告诉模型密码是 A
token 2~199：都是无关内容
token 200：问“密码是什么？”
```

即使你有 100 层 RNN，TBPTT 只有 50，token 200 的错误仍然没办法通过梯度直接追到 token 1。

100 层可以把 token 200 当前的表示加工得非常复杂，但它不能把“时间上的 199 步距离”变成“网络深度上的 100 层”。

所以你现在可以把 RNN 想成一个二维网格：

> 纵向 = 特征抽象深度；横向 = 时间记忆长度。

TBPTT 截的是横向，不是纵向。

### 完全计算

完整 BPTT：把整个序列的时间依赖全部展开后再反向传播。

问题：

- 计算很慢
- 显存开销大
- 容易梯度爆炸/消失
- 对早期状态非常敏感，训练不稳定

所以实践中几乎不用“完整 BPTT”，通常采用截断 BPTT。

### 截断时间步

截断 BPTT：

> 只让梯度沿时间向前回传最近 $\tau$ 步，更早的梯度直接截断。

优点：

- 计算更快
- 显存更省
- 训练更稳定

代价：

> 更偏向学习短期依赖，长距离 credit assignment 会变弱。

### 随机截断

这里的“随机截断”可以理解成：

> 不再固定“每次只反传 50 步”，而是在每个时间步随机决定：梯度继续往前传，还是在这里截断。

例如反向传播可能随机变成：

```text
这次：
loss ← h200 ← h199 ← h198 ✂

下次：
loss ← h200 ← h199 ← ... ← h180 ✂

偶尔：
loss ← h200 ← ... ← h50 ✂
```

关键是它不能随便截，否则梯度会系统性偏小。

所以教材引入随机变量 $\xi_t$：

- 大多数时候取 0：在这里截断。
- 少数时候取一个大于 1 的值：继续传播，并把这条少见的长路径“加权放大”。

设计成：

$E[\xi_t]=1$

因此从平均意义上看：

> 虽然单次反向传播是不完整的，但重复很多次以后，平均梯度等于完整 BPTT 的真实梯度。

这就是它相比固定截断的优势。

固定截断：

> 超过 $\tau$ 步的梯度永远没有，存在偏差。

随机截断：

> 长距离梯度虽然很少计算，但偶尔会计算，并且给予更大权重，因此期望上不丢失。

代价是梯度方差会很大：有时突然出现一条很长、权重很大的梯度路径，训练可能比较不稳定。

一句话：

> 随机截断 = 大多数时候只算短距离梯度，偶尔算长距离梯度并放大补偿，从而用较低平均成本近似完整 BPTT，而且期望上无偏。

### 等一下，我突然回忆起来，你刚才说隐藏层和时间步是正交的，那么他们的计算是并行的吗？还是必须一层的隐藏层必须瞪上一层的时间步全部处理完才能进入下一个隐藏层的计算？

不是“第一层把所有时间步都算完，第二层才开始”。标准多层 RNN 是交错推进的。

第 $l$ 层、时间步 $t$ 的隐藏状态通常依赖两个东西：

$h_t^{(l)} = f\left( h_t^{(l-1)}, h_{t-1}^{(l)} \right)$

也就是它必须等：

- 下层在当前时间步的结果 $h_t^{(l-1)}$
- 本层在上一时间步的结果 $h_{t-1}^{(l)}$

例如两层 RNN：

```text
时间 →      t=1       t=2       t=3

第2层       h²₁  →    h²₂  →    h²₃
             ↑         ↑         ↑
第1层       h¹₁  →    h¹₂  →    h¹₃
             ↑         ↑         ↑
输入         x₁        x₂        x₃
```

计算顺序大致是：

```text
h¹₁
 ↓
h²₁

同时继续：
h¹₁ → h¹₂
        ↓
       h²₂
```

所以不是：

```text
错误理解：
第1层：t1 t2 t3 ... 全算完
↓
第2层：t1 t2 t3 ... 再算
```

而是像一个“二维波前”向右上方推进。

但注意，它也不能完全并行：

> 同一 RNN 层的时间步有递归依赖，所以 $t+1$ 必须等 $t$ 的隐藏状态。

这正是传统 RNN 相比 Transformer 难以高度并行的一个重要原因。

一句话：

> 深度轴和时间轴概念上正交，但计算依赖交织在一起；既不是完全并行，也不需要一整层全部算完再进入下一层。
