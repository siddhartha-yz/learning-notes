# 用PyTorch实现线性回归

```python
for epoch in range(100):
    y_pred = model(x_data)
    loss = criterion(y_pred, y_data)
    print(epoch, loss)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

### 为什么这里先清空优化器中的梯度再进行反向传播和更新？反向传播和更新难道不是依赖暂时存储的梯度的吗？

因为 `zero_grad()` 清空的是“上一轮残留的梯度”，不是这一轮即将使用的梯度。

执行顺序是：

```text
optimizer.zero_grad()
        ↓
清空上一轮 grad
        ↓
loss.backward()
        ↓
根据当前 loss 重新计算梯度，并写入参数的 .grad
        ↓
optimizer.step()
        ↓
利用刚算出的 .grad 更新参数
```

关键点：PyTorch 默认会累加梯度。

如果不清零：

```text
第1轮 grad = g1
第2轮 backward 后 grad = g1 + g2
第3轮 = g1 + g2 + g3
```

通常这不是我们想要的。

所以这里：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

完全没问题。`step()` 用的是 `backward()` 刚刚算出来并暂存在 `.grad` 里的梯度。

其实也可以写成：

```python
loss.backward()
optimizer.step()
optimizer.zero_grad()
```

只要保证“下一次 backward 前梯度已经清空”即可。前一种写法更常见。



``` python
size_average and reduce args will be deprecated, please use reduction='sum' instead.
  self.reduction: str = _Reduction.legacy_get_string(size_average, reduce)
    
这里是什么意思？下面是我对应的源代码：

criterion = torch.nn.MSELoss(size_average=False)
```

意思是：你这句用了旧版参数写法。

```python
criterion = torch.nn.MSELoss(size_average=False)
```

其中：

```python
size_average=False
```

旧含义是：不要对所有样本的平方误差取平均，而是直接求和。

也就是从：

$\text{MSE}=\frac{1}{N}\sum_i(\hat y_i-y_i)^2$

变成：

$\sum_i(\hat y_i-y_i)^2$

新版 PyTorch 推荐直接写：

```python
criterion = torch.nn.MSELoss(reduction='sum')
```

对应关系很简单：

```text
旧：size_average=True   → 新：reduction='mean'
旧：size_average=False  → 新：reduction='sum'
```

所以这只是弃用警告，不是报错。把你的代码改成：

```python
criterion = torch.nn.MSELoss(reduction='sum')
```

即可。



``` python
import torch

x_data = torch.tensor([[1.0],[2.0],[3.0]])
y_data = torch.tensor([[2.0],[4.0],[6.0]])

class LinearModel(torch.nn.Module):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.linear = torch.nn.Linear(1,1)

    def forward(self, x):
        y_pred = self.linear(x)
        return y_pred

model = LinearModel()
criterion = torch.nn.MSELoss(reduction='mean')
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)

for epoch in range(100):
    y_pred = model(x_data)
    loss = criterion(y_pred, y_data)
    print(epoch, loss)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

print('w=',model.linear.weight.item())
print('b=',model.linear.bias.item())

x_test = torch.tensor([[4.0]])
y_test = model(x_test)
print('y_pred=',y_test.detach())
```

### 我发现把reduction从sum改成mean之后，经过100epoch，最终的w从2.0144400596618652变为了1.4013491868972778基本上等价于学习率降低，这是因为loss从sum改成mean之后，梯度变小，从而导致梯度下降的速度变慢了吗？能不能算出来mean相对于sum的等价学习率？

对，你的判断是对的。

如果同一批里有 $N$ 个 loss 元素：

`sum`：

$L_{\text{sum}}=\sum_{i=1}^N L_i$

所以梯度：

$\nabla L_{\text{sum}}=\sum_{i=1}^N \nabla L_i$

`mean`：

$L_{\text{mean}}=\frac{1}{N}\sum_{i=1}^N L_i$

所以：

$\nabla L_{\text{mean}} =\frac{1}{N}\nabla L_{\text{sum}}$

因此用普通 SGD：

$w\leftarrow w-\eta\nabla L$

如果想让 `mean` 和 `sum` 每一步更新完全等价，就要：

$\boxed{\eta_{\text{mean}}=N\eta_{\text{sum}}}$

例如你的数据如果一次输入 3 个标量样本：

```python
x = [1, 2, 3]
```

那么：

```text
sum + lr=0.01
```

约等价于：

```text
mean + lr=0.03
```

反过来：

```text
mean + lr=0.01
```

约等价于：

```text
sum + lr=0.00333
```

所以你观察到 `mean` 后 100 epoch 只到 `1.40`，本质上就是：**梯度缩小了 3 倍，而学习率没变，因此参数移动速度也大约缩小了 3 倍。**

补一个细节：`MSELoss(reduction="mean")` 除的是 loss 中的**元素总数**，不一定只是 batch size。比如输出形状是 `(32, 10)`，那么是除以 $32\times10=320$。

对于纯 SGD、无 momentum/weight decay 时，这个学习率换算可以做到严格等价；加入 momentum、weight decay、Adam 等以后就不再这么简单。



## 总结

这节主要讲：**用 PyTorch 框架重写之前手写的线性回归训练流程。**

核心就四步：

1. 准备数据
   用 Tensor 表示输入和标签；mini-batch 时通常按“样本数 × 特征数”的矩阵组织。
2. 定义模型
   模型继承：

```python
torch.nn.Module
```

至少实现：

```python
__init__()
forward()
```

线性层通常用：

```python
torch.nn.Linear(in_features, out_features)
```

它自动包含权重 `w` 和偏置 `b`。

1. 定义损失函数和优化器

```python
criterion = torch.nn.MSELoss(...)
optimizer = torch.optim.SGD(model.parameters(), lr=...)
```

`model.parameters()` 会自动收集模型中所有需要训练的参数。

1. 训练循环

```python
for epoch in range(...):
    y_pred = model(x_data)
    loss = criterion(y_pred, y_data)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

流程就是：

```text
forward
→ 算 loss
→ 清梯度
→ backward
→ optimizer.step()
```

即：

```text
前馈 → 反馈 → 更新
```



这节还强调两点：

- loss 最终要归约成标量，方便 `backward()`。
- 训练轮数太少可能没收敛；训练太久又可能过拟合，因此不能只看训练集 loss。

一句话总结：

> 以前是手写 forward、梯度和参数更新；这一节开始正式用 `Module + Loss + Optimizer + backward()` 搭建标准 PyTorch 训练流程。
